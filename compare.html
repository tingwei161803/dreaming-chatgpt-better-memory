ChatGPT × Claude:兩種做夢

同一個比喻,兩種做法。OpenAI 把「做夢」做成 ChatGPT 裡看不見的背景功能;Anthropic 則把它拆成開發者自己組裝、調整、稽核的元件,並公開研究數據。以下依三份一手資料逐項對照。

01

同一個直覺

兩邊都把做夢定義為:趁沒人在等的時候回頭整理過去的對話,讓下一次一開始就有對的脈絡。Anthropic 直接點名靈感來源:睡眠時海馬迴的重播,以及 Letta 與 UC Berkeley 提出的「sleep-time compute」。

02

服務的對象不同

ChatGPT 的做夢記的是「你這個人」,自動發生,你看得到的是一頁摘要。Claude 的 cookbook 記的是「你的 agent 學到的事」,何時跑、讀哪些逐字稿、記憶長什麼樣,都由開發者決定。

03

公開程度不同

OpenAI 的評測以圖表呈現、沒有可引用的數字,也沒有描述架構。Anthropic 把每一份 prompt 全文印出來,附上實測成本,並公布評測百分比。

比較面向ChatGPT 做夢OpenAI · 2026/6/4 公告Claude 做夢Anthropic · 2026/11/2 cookbook + 11/6 研究文
定位
是什麼「建立在做夢之上、明顯更強也更省算力的記憶架構」——就是 ChatGPT 的記憶系統本身。一份 cookbook,教你用 Managed Agents 的動態工作流程做出「一個小而可用的夢」。另有官方的 Dreams 研究預覽版:讀取 memory store 與過去的 session,把整理後的版本寫進新的 store。
誰在用ChatGPT 使用者。2026/6/4 起美國 Plus、Pro 可用;更多國家與 Free、Go 於之後數週陸續開放。用 Claude API 打造 agent、且有 Managed Agents beta 權限的開發者(Python 3.11 以上、anthropic SDK 2.x)。
記住什麼你這個人:偏好、專案與限制——例如你的水下相機組合、你吃素、你 7 月要去新加坡。agent 工作中學到的事:有效的指令與旗標、做過的決定與時間、吃過虧才學到的教訓。改寫 INSTRUCTIONS,也能改成以「一個人」為中心整理。
怎麼運作
讀什麼你的對話歷史,跨很多段對話。agent 已結束的 session,每個匯出成一份純文字逐字稿。其他 agent 的紀錄也行(.txt、.log、.json、.jsonl、.md)。
什麼時候跑背景程序。公告沒有說明多久跑一次。你手動跑 notebook 時,或用 cron 每晚 1 點跑 dreaming_nightly.py。每次只取上次之後建立的 session,當下還在跑的會跳過。
誰在做公告未說明。三種 agent。lead(Claude Sonnet 5.5)撰寫並啟動工作流程;每份逐字稿一個 analyzer(Claude Haiku 5.5),約 20 份一組;最後由 organizer(Claude Haiku 5.5)整理一次。
做法公告未說明。目標是新鮮、連續、相關。每個 analyzer 先讀完整份逐字稿,再驗證記憶裡既有的說法、補上細節(識別碼、指令、過時註記、教訓),最後整理成互相連結的小檔案。
產出與使用
記憶長什麼樣一個整理過的「記憶狀態」。你看得到的是記憶摘要頁上的重點。一套 wiki:附 frontmatter 的 Markdown 小檔,用 [[slug]] 互相連結,_index.md 當目錄,存在 Managed Agents 的 memory store。
下一次怎麼用新對話從共享脈絡開始,不用每次重新自我介紹。agent 以唯讀方式掛載 store。也可以把一個小檔(例如 _index.md)當作掛載說明放進 system prompt,上限 4,096 字元。
能調整什麼在摘要頁新增或更新資訊,指定哪些主題該在何時提起;也可以直接問模型。全部:analyzer 與 organizer 的 prompt、INSTRUCTIONS、三個模型、排程、讀哪些逐字稿、更新哪個 store。
保持正確
時間與過時「與時俱進」是三大目標之一:行程結束後,「你 7 月要去新加坡」會改成「你 2026 年 7 月去了新加坡」。事實都附日期。後來的更正會保留舊值,並註明兩邊的日期與來源;兩個說法互相矛盾、又分不出先後時,organizer 會標 CONFLICT,不會猜。
修正錯誤這套系統的目標之一是解決過時、出錯與規模化,但沒有說明怎麼修正。做夢會拿原始逐字稿核對筆記。Pokémon 實驗裡,一條「PokéCenter 在月見山哪一側」的錯誤筆記被改正後,Claude 回到洞窟,最後抵達華藍市。
公開的數字三個面向、2024/2025/2026 三個世代的評測,以圖表呈現,沒有可引用的百分比。很多。例如 wiki 隨做夢從 2 個 session 增加到 128 個,25 題的得分從 13% 升到 48%;改寫指令後,合約條款從 57 條留住 41 條變成 57 條全留。
安全、隱私與成本
Prompt injection公告未提及。逐字稿一律當資料,不當指令。analyzer 只有 read、write、edit、glob、grep 五個檔案工具,沒有 shell,網路白名單是空的;agent 以唯讀方式掛載成品。
機密與保留公告未提及;控制方式請見 OpenAI 的 Memory FAQ。不把憑證抄進記憶。Managed Agents 的 session 不適用零資料保留(ZDR)與 HIPAA,所以 notebook 匯出後就刪掉 session。每次寫入都是一個 memory version,可稽核 30 天。
成本服務免費版的算力約降低 5×,Plus、Pro 的記憶容量也會增加。包含在 ChatGPT 方案內(含免費版),不按次計費。每次執行照定價付費。範例 11 份逐字稿(283 KB):$0.36,約 2.5 分鐘。50 份長逐字稿(約 12 MB):約 $8,約 10 分鐘。估價超過 BUDGET_USD(預設 $40)就不會開跑。
使用前審閱摘要頁隨時可以看。預設不審閱:一份有問題的逐字稿,隔天早上就可能影響 agent。想先審,就寫進新的 store,讀過再讓 agent 改用它。

共同點

  • 記憶是事後整理的。ChatGPT 不再靠你說「記住這個」;Anthropic 把建立記憶的工作推到背景,不讓 agent 分心。
  • 時間是核心問題。ChatGPT 會在行程結束後改寫記憶;Claude 的記憶每條事實都附日期,並記下誰取代了誰。
  • 記憶要能被檢視。ChatGPT 有摘要頁;Claude 的記憶就是一堆你打得開的 Markdown 檔,外加版本紀錄。

關鍵差異

黑盒與白盒

OpenAI 說明了做夢達成什麼,沒說怎麼做到。Anthropic 的 cookbook 把四份 prompt 檔全文印出來,還告訴你想改哪個行為就改哪一行。

誰付錢、誰決定節奏

ChatGPT 的成本是 OpenAI 自己要解決的工程問題(約 5× 的降幅讓免費版成為可能)。Claude 則由開發者自己決定排程、模型與預算上限,每次執行都看得到帳單。

安全假設

Claude 的設計假設逐字稿裡可能有惡意文字,所以處處限縮 agent 的權限。OpenAI 的公告沒有談到這一塊。這不代表 ChatGPT 沒有防護,只是公告沒有寫。

本站觀點

以下為本站觀點,非原文內容

以下是本站讀完三份資料後的看法,不是 OpenAI 或 Anthropic 的說法。

  • 如果你是 ChatGPT 使用者:做夢開箱即用。值得養成的習慣是偶爾看一下摘要頁,不想讓它學到的話題就用臨時對話。
  • 如果你在做 agent:這份 cookbook 是真的能上線的範本。研究文的經驗也適用於任何記憶系統:告訴模型記憶「用來做什麼」,而不是規定它「怎麼記」;每次都會載入的那一層要小;wiki 要搭配搜尋。
  • 兩邊都還沒解決的是:什麼時候該寫記憶、怎麼保持最新、多久做一次夢。Anthropic 在研究文結尾把這三件事列為開放問題。
